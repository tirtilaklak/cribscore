# Journal domain contract

Versioned ledger: `{schemaVersion:'cribscore_journal_v1',journalId,createdAt,revision,events}`. Events are append-only `{id,kind,at,data}`; revision equals event count. Existing events and original publication bytes never change. ISO timestamps are exact UTC; money/price decimal strings have at most six fractional places and quantity strings at most eight. Long positions use weighted average cost with half-up cash rounding; quantities are never inferred for actual trades.

Default paper configuration: USD100 fixed notional, USD0 commission per fill, 5 basis points estimated adverse slippage per fill, SPY same-window benchmark. Configuration is explicitly assumed, configurable and frozen on each paper intent. No fabricated positions or sample data are created.

`createJournal({journalId,at})`; `validateJournal(value)` (async, SHA256 bindings included); `checkAppendOnly(previous,next)`; `appendSettings(journal,{id,at,settings})`; `recordAbstention(journal,{id,at,date,horizonId,unrankedCount,snapshot,reason})`; `enrollPublication(journal,{id,at,publication,windowResolution,settings})`; `evaluatePaper(journal,{at,eventIdPrefix,calendar,seriesBySymbol,reviewsBySymbol,resolvers})`; `recordActualConfirmation(journal,{id,at,intentId,confirmed:true})`; `recordActualFill(journal,{id,at,intentId,side,occurredAt,quantity,price,fee,currency})`; `reviseActualFill(journal,{id,at,fillId,replacement,reason})` return `{ok,journal,...}` or `{ok:false,errors}`. No method mutates its input.

Publication envelope: `{publicationId,publishedAt,payloadHash,payloadBytes,policyVersion,snapshotVersion,horizonId,entities:[{symbol,entityId}]}`. `payloadBytes` is exact approved slate JSON, distinct from actual publication time. The host must obtain the envelope from an authoritative approved publisher. Shape/hash validation is not authentication. Current approved publisher remains null; no envelope is invented from generated_at or the six unranked cases.

Paper intent must be enrolled before the resolved next regular open strictly after publication, and the resolved 1/5-session window must match the published window. Delayed bars may settle enrolled intent after the event; previously unseen suggestions are no-fill. Verified calendar/price/action resolvers are injected from `dist/lib/prices.js`. Missing inputs preserve pending/blocked/no-fill with reasons. Splits/dividends require complete, explicit action coverage. Benchmarks use identical entry/exit sessions and cost assumptions.

`calculateLongPosition({fills,mark,actions,currency})` is a pure accounting projection. `projectJournal(journal,{storage})` yields `cribscore_journal_view_v1` with settings, storage, counts, entries, immutable context, paper/actual accounting, actual effective fills and revisions. Null amounts mean unknown; no missing amount becomes zero.

`exportJournal(journal)`; `previewImport(current,text)`; `applyImport(current,preview)`. Preview is required; stale preview or conflicting IDs/history is rejected. Identical events are deduplicated. Additive, valid histories preserve original records and ordering. Unknown schemas, malformed data, oversized files and inconsistent publication hashes are rejected.

`createLocalJournalStore({storage,key})` and `createHttpJournalStore({fetch,url})` expose `load()` and `commit(journal,{expectedRevision})`. HTTP is the preferred durable store; local data is labeled local-only. Storage failures never claim saved/synced. HTTP RPC: GET success `{ok:true,journal:null|object,revision}`; POST body `{expectedRevision,journal}`; successful POST same response; conflict409 `{ok:false,error:'revision_conflict',revision,journal}`. Server validates, checks append-only prefix and uses an owner-scoped atomic revision compare-and-swap. Owner identity comes from existing private Site authentication, never client JSON.


Additional contracts:

- Entity binding is mandatory for publication suggestions and every paper mark. Optional settings.benchmarkEntityId defaults null; unavailable identity keeps the benchmark pending. A ticker alone never establishes security identity.
- `recordActualActionReview(journal,{id,at,intentId,fromAt,throughAt,coverage,reviewMark})` stores separately reviewed actual holding-period action coverage. Without it actual P&L stays pending; paper action intervals are not borrowed for actual fills.
- `revisePaperEvaluation(journal,{id,at,evaluationId,replacement,reason})` deliberately appends a restatement linked to the latest evaluation. Original publication, configuration, window, evidence and outcomes stay in the event stream. Stale revision targets are rejected. Routine late benchmark completion may append while the own closed outcome stays fixed.
- Dividend accrual is an ex-date receivable, distinct from cash paid and from realized trading P&L. `dividendAccrual` contributes to `totalPnl` and matched benchmark total P&L; `realizedPnl` includes completed sales only. Marks preceding included effective share/distribution actions cannot establish open/total P&L.
- Paper quantity is rounded down to 8 decimals within the fixed notional INCLUDING entry commission. Adverse execution price uses assumed slippage. Projection splits commissionCosts and slippageCosts; `costs` is their sum. Daily O/C is a paper reference, not an auction or actual fill.
- Explicit `previewImport(current,text,{mode:'restore'})` can adopt backup identity only when the current journal is empty. Ordinary merge rejects different identities. `applyImport` consumes a current, unmodified preview. `checkAppendOnly(previous,next,{allowEmptyRestore:true})` allows identity adoption only for revision 0 / empty history; HTTP commit may include `mode:'restore'`, expectedRevision 0. Nonempty history is never replaced.
- Host must separately reject new publication events while the authoritative publisher is unconfigured. The browser module, imports and SHA256 do not authenticate a publisher.
